# 前端登录与用户级会话隔离设计

## 背景

当前原生 HTML 前端会在启动时从 URL 参数、`localStorage` 和默认值中解析 `userId`，后续会话列表、历史消息、Agent 执行和记忆同步也依赖前端传入的 `userId`。这种方式适合本地调试，但不适合作为正式身份边界，因为调用方可以手工修改 `userId` 访问或续接其他用户会话。

本次改动将身份来源收敛为服务端认证结果。用户可以通过账号密码登录，也可以以游客身份进入。前端只负责保存 token 并在请求中携带，后端从认证上下文中取得当前用户，再按当前用户隔离会话。

本设计仅覆盖：

1. 登录界面支持账号和密码登录。
2. 支持游客模式，游客 `userId` 由后端随机生成。
3. 用户级别的会话列表、历史消息、执行续接、记忆同步和单会话删除隔离。
3. 页面内支持指定或修改当前 `sessionId`。
4. 删除指定对话时保留已经同步到 Mem0 的长期记忆。

不引入 API Key、计费、分组、额度、IP 白名单、OAuth、2FA、开放注册或管理后台。

## 设计原则

- 身份只能来自服务端认证结果，不能信任前端手填的 `userId`。
- `sessionId` 是用户可指定的会话标识，但能否读取、续接或删除必须由后端按当前登录用户判断。
- 删除会话只删除本站会话记录和消息历史，不删除 Mem0 长期记忆。
- 认证能力保持最小可用，先满足账号密码登录、游客进入和用户隔离，不扩展网关场景。

## 交互设计

### 登录界面

未登录用户访问页面时展示登录界面，包含：

- 账号输入框。
- 密码输入框。
- 登录按钮。
- 游客进入按钮。
- 登录失败提示区域。

账号可以使用系统内用户唯一标识，例如 `username` 或 `email`。本次实现选择一个字段作为账号入口，后端按该字段查询用户。登录成功后前端保存访问 token 和当前用户展示信息，进入聊天界面并加载该用户的会话列表。

登录失败时保留输入内容中的账号，清空或保留密码由前端实现决定，但错误提示不得暴露账号是否存在，只展示统一的“账号或密码错误”语义。用户状态禁用、token 失效、未登录访问受保护接口时，前端回到登录界面。

### 游客模式

游客模式不要求输入账号和密码。用户点击游客进入时，前端调用游客接口，由后端生成随机 `userId`，例如 `guest_8f3a9c2e7b4d`，写入用户表并返回 token。后续请求和账号用户一样携带 `Authorization: Bearer <token>`。

页面启动时，如果本地存在 token，前端先调用 `/api/v1/auth/me` 尝试恢复身份。恢复成功时继续使用 token 中解析出的原 `userId`，包括游客用户；恢复失败、token 不存在或 token 已过期时，前端展示登录界面，用户可以账号登录或重新进入游客模式。重新进入游客模式会创建新的随机 `userId`，不会自动继承旧游客会话。

### 登录后的用户展示

聊天界面底部状态条继续展示当前用户和当前会话，但用户信息为只读展示，来源于 `/api/v1/auth/me` 或登录响应，不提供“修改 userId”输入。

用户可执行：

- 查看当前登录用户。
- 指定或修改当前 `sessionId`。
- 从会话列表切换已有会话。
- 删除指定会话。
- 退出登录。

退出登录时前端清理 token、当前用户、会话列表和当前消息展示，回到登录界面。本阶段不要求服务端 token 黑名单；如后续需要强制登出，可单独设计 token 撤销能力。

切换登录用户时必须按退出登录同等语义处理旧状态。无论是账号 A 退出后账号 B 登录，还是游客身份切换为账号登录，前端都必须先停止当前流式请求，清理旧 token、当前用户、会话列表、当前消息、分页游标、正在输入但尚未发送的会话绑定状态和错误提示，再保存新 token 并加载新用户会话列表，避免旧用户会话或 SSE 响应残留到新用户界面。

### 会话 ID 设置

保留页面底部现有会话 ID 状态展示，在其右侧增加设置按钮。点击后打开紧凑弹层，仅包含：

- 会话 ID 输入框。
- 取消按钮。
- 应用按钮。

`sessionId` 输入值仅允许字母、数字、下划线和连字符，长度为 1 到 64 个字符。校验失败时使用现有非阻塞 Toast 展示错误，不关闭弹层。

点击应用后：

1. 如果存在活动请求，先取消该请求，避免旧会话响应覆盖新状态。
2. 更新页面内的当前 `sessionId`。
3. 请求当前登录用户下的对应历史消息。
4. 若会话不存在，则展示空态，后续发送会以当前登录用户创建该会话。
5. 若会话已被其他用户占用，后端返回不可用错误，前端拒绝切换并保留原状态。

### 删除指定会话

会话列表项在悬停或键盘聚焦时显示删除图标按钮，并提供可访问名称。点击删除按钮不得触发会话切换，而是打开确认对话框，明确展示将删除的会话 ID，并提示已同步到 Mem0 的长期记忆将保留。

确认后调用单会话删除接口：

- 成功：从列表移除该项并显示成功 Toast。
- 删除的是当前会话：清空当前展示，生成新的会话 ID，并回到通用对话空态。
- 删除的不是当前会话：保持当前聊天内容和会话 ID 不变。
- 失败：保留列表项和当前页面状态，显示后端错误信息或通用失败提示。

如果当前会话存在活动请求，前端不允许直接删除该会话，提示用户先取消任务。其他非活动会话仍可删除。

## 后端接口设计

### 认证接口

新增登录接口：

```http
POST /api/v1/auth/login
Content-Type: application/json
```

请求：

```json
{
  "account": "demo-user",
  "password": "******"
}
```

成功响应沿用统一响应结构：

```json
{
  "code": "200",
  "info": "success",
  "data": {
    "accessToken": "jwt-token",
    "tokenType": "Bearer",
    "user": {
      "userId": "demo-user",
      "account": "demo-user"
    }
  }
}
```

新增游客接口：

```http
POST /api/v1/auth/guest
```

成功响应与登录接口一致，但用户类型为游客，`account` 为空。

新增当前用户接口：

```http
GET /api/v1/auth/me
Authorization: Bearer <accessToken>
```

成功时返回当前登录用户的只读信息。未登录、token 非法、token 过期或用户禁用时返回认证失败。

### 会话接口

所有受保护接口通过请求头携带 token：

```http
Authorization: Bearer <accessToken>
```

会话列表：

```http
GET /api/v1/session/list
Authorization: Bearer <accessToken>
```

历史消息：

```http
GET /api/v1/session/{sessionId}/messages?cursorIndex={cursorIndex}
Authorization: Bearer <accessToken>
```

删除会话：

```http
DELETE /api/v1/session/{sessionId}
Authorization: Bearer <accessToken>
```

长期记忆同步：

```http
POST /api/v1/session/{sessionId}/sync-memory
Authorization: Bearer <accessToken>
```

通用 Agent、巡检 Agent 和股票分析请求继续携带 `sessionId`，但不再携带可信 `userId`。后端从认证上下文取得当前用户后执行会话所有权校验。

### SSE 流式接口认证

通用 Agent、巡检 Agent 和股票分析都是 `POST + text/event-stream` 风格的流式接口。前端应继续使用 `fetch` 发起请求，并在请求头携带：

```http
Authorization: Bearer <accessToken>
Accept: text/event-stream
```

前端从 `response.body.getReader()` 读取 SSE 数据并沿用现有解析逻辑。不要改成原生 `EventSource`，因为 `EventSource` 不能设置自定义 `Authorization` 请求头；也不要把长期访问 token 拼到 URL query 参数中，避免被浏览器历史、代理日志或服务端访问日志记录。

当 SSE 请求返回 `401` 时，前端关闭当前流式状态，清理登录态并回到登录界面。若返回会话归属冲突或参数错误，前端只展示业务错误，不清理 token。

## 服务与数据边界

### 用户认证

新增最小用户表或复用现有用户表，至少包含：

- `user_id`：业务用户 ID，作为会话归属字段。
- `user_type`：用户类型，支持 `ACCOUNT` 和 `GUEST`。
- `account`：登录账号，可空；账号用户唯一，游客为空。
- `password_hash`：密码哈希，可空；账号用户必填，游客为空。
- `status`：用户状态，至少支持 active/disabled。
- `created_at`、`updated_at`。

密码使用后端安全哈希算法存储。登录时只返回统一错误，不暴露账号是否存在。游客用户由后端生成唯一 `user_id` 并入库，`account` 和 `password_hash` 保持为空。JWT 中包含用户 ID、用户类型、签发时间和过期时间。后端认证过滤器校验 token 后应回库检查用户状态，避免禁用用户继续访问。

初始账号使用 SQL 初始化，不通过应用配置自动创建。SQL 中只保存哈希后的密码，不保存明文密码。JWT 密钥和过期时间通过应用配置提供，最小配置项为 `auth.jwt.secret` 和 `auth.jwt.expires-in-seconds`；生产环境必须用环境变量覆盖默认密钥。

### 会话所有权

新增或调整统一会话所有权服务：

```java
public enum SessionAccessState {
    AVAILABLE,
    OWNED,
    UNAVAILABLE
}
```

服务入参为当前登录用户 ID 和 `sessionId`，其中当前登录用户 ID 来自认证上下文，而不是请求参数。

- `AVAILABLE`：会话不存在，当前用户可以创建。
- `OWNED`：会话属于当前用户。
- `UNAVAILABLE`：会话存在但属于其他用户。

历史查询、通用 Agent、巡检 Agent、股票分析、记忆同步和删除会话复用该服务。

### 删除事务

新增会话删除服务，负责一个明确事务边界：

1. 从认证上下文取得当前用户 ID。
2. 按当前用户 ID 和 `sessionId` 查询并确认会话所有权。
3. 删除 `ai_chat_message` 中该会话的全部消息。
4. 删除 `ai_chat_session` 中当前用户拥有的对应会话记录。
5. 数据库事务提交后，清理该会话的 Redis/进程内运行时缓存和活动跟踪状态。

删除接口不调用 Mem0 删除能力，也不修改长期记忆同步记录之外的任何 Mem0 数据。

### 执行与删除互斥

现有活动跟踪不能准确表示异步任务仍在执行。新增轻量会话操作注册器，将每个登录用户下的会话标记为 `EXECUTING` 或 `DELETING`。执行入口在调度任务前获得执行占用，删除入口获得删除占用，二者互斥。任务完成、异常或取消时必须释放占用。

## 状态与数据流

```text
页面启动 -> 本地存在 token -> GET /auth/me
       -> 成功：恢复账号或游客身份，加载会话列表
       -> 失败：清理 token，展示登录界面

未登录 -> 登录页 -> POST /auth/login 或 POST /auth/guest
       -> 保存 token -> GET /auth/me -> 加载当前用户会话列表 -> 进入聊天界面

设置会话 ID -> 校验 sessionId -> 取消活动请求
             -> GET /session/{sessionId}/messages
             -> 已拥有：展示历史
             -> 不存在：展示空态，后续创建
             -> 其他用户占用：拒绝切换

删除会话 -> 二次确认 -> DELETE /session/{sessionId}
         -> 认证过滤器解析当前用户
         -> 所有权校验
         -> 事务删除消息与会话
         -> 清理派生缓存，保留 Mem0
         -> 前端移除列表项并修正当前会话状态
```

## 错误处理

- 未登录访问受保护接口：返回认证失败，前端回到登录界面。
- 登录失败：统一提示账号或密码错误，不泄露账号存在性。
- 游客恢复失败：清理旧 token，回到登录界面；再次进入游客模式时创建新的随机 `userId`。
- 用户禁用：返回认证失败或无权访问，前端清理登录态。
- 非法 `sessionId`：前端阻止提交；后端仍独立校验。
- 历史会话不存在：手工指定会话时显示空态，不视为页面错误。
- 会话已属于其他用户：拒绝加载历史和发起任务，保留切换前的页面状态。
- 删除不存在或无权访问的会话：返回统一失败，前端不移除列表项。
- 删除请求网络失败：恢复删除按钮并允许重试。
- 活动请求期间切换会话：先取消活动请求，再应用新值。
- 活动请求期间删除当前会话：前端拒绝并提示先取消。
- `localStorage` 不可用：登录态无法持久化时仍可在当前页面内使用内存 token，刷新后需要重新登录。

## 验收标准

1. 用户可以通过账号密码登录或游客模式进入聊天界面。
2. 游客 `userId` 由后端随机生成并入库；有效 token 可恢复原游客身份，解析失败后重新进入游客模式会生成新 `userId`。
3. 进入聊天界面后的所有受保护请求都携带认证 token，后端从 token 解析当前用户。
4. 前端不再提供可编辑 `userId` 作为正式身份入口。
5. 会话列表、历史消息、Agent 执行、股票分析、记忆同步和删除会话均按当前用户隔离。
6. 用户可手工指定合法 `sessionId`；已有自有会话加载历史，不存在会话进入空态，其他用户会话不可访问。
7. 用户只能删除自己拥有的指定会话，消息和会话数据库记录一并删除。
8. 删除当前会话后页面进入新的空会话，删除其他会话不影响当前内容。
9. 已同步到 Mem0 的长期记忆在删除会话后仍然保留。
10. 失败、取消、窄屏和键盘操作均不会导致页面进入不可恢复状态。
