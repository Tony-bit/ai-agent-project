# AI 应用后端与 Java 后端双版本简历设计

## 背景

当前简历以“AI 应用开发工程师”为唯一定位，同时用于投递 AI 应用岗位和普通 Java 后端岗位。现有内容事实与指标已经由候选人确认，但单一版本同时承载两类岗位诉求，导致招聘信号不够聚焦：AI 项目在第一页占比过高，普通后端岗位难以快速识别业务后端能力；两页内容分布也不均衡，第一页过密，第二页下半页留白较多。

## 目标

基于现有 PDF 简历制作两套事实一致、岗位定位不同的中文简历：

1. `AI 应用开发工程师（Java）`版本，突出 Agent 工程落地、模型可靠性和量化评测能力。
2. `Java 后端开发工程师`版本，突出大流量业务、性能优化、缓存、消息治理和稳定交付能力。

两套简历均采用 A4 两页单栏结构，提供可编辑 `DOCX` 和投递用 `PDF`，保证 ATS 可解析、指标可复制、链接可点击。

## 非目标

- 不新增、推测或修改未经候选人确认的业务事实与指标。
- 不把个人 Agent 项目包装为正式任职经历。
- 不隐藏 Shopee 的短期任职经历。
- 不在本轮继续扩展 Agent 项目功能。
- 不在仓库安全历史完成清理前向简历加入代码仓库链接。

## 事实口径

- Shopee 任职时间统一为 `2025.06-2025.09`，与实际离职月份一致。
- Agent 项目的 LoRA/SFT 数据、训练过程和评测指标均有可核验证据，可保留。
- Shopee 的消息乱序治理机制由候选人真实完成。
- 华为榜单项目中的 DDD 与版本化重构、TP99 优化、Redis 内存优化、智能巡检 Agent 与 MCP 工具及相关指标均为候选人真实完成。
- Redis 指标统一表述为“内存占用降低 30%，节省约 12GB”，消除原有歧义。
- 智能驾驶云项目沿用已确认的业务规模和告警监控体系职责，不额外扩写。

## 文案原则

- 每个要点优先表达“问题或目标、个人行动、可核验结果”。
- 明确区分“主导、设计并实现、负责、参与”等责任边界。
- 保留真实量化指标，但避免同一段落堆叠过多数字和技术名词。
- AI 版本强调工程落地与可靠性，不将项目描述成算法研究岗位。
- Java 版本强调业务后端能力，Agent 项目只承担差异化加分作用。
- 删除工作经历与项目经历之间的重复句子。
- 不使用“精通”“专家”等无法由经历直接证明的自评。

## 视觉设计

- A4、两页、单栏，不使用复杂表格、技能进度条或多栏布局。
- 姓名作为页首主标题，删除“求职者信息”标题。
- 联系方式、目标岗位和在线演示集中在页首。
- 使用克制的深蓝色标题与黑灰正文，移除占空间较多的图标和大面积灰色标题条。
- 正文字号约 `10pt`，项目要点保持两至三行，关键指标可加粗但不使用多种强调色。
- 项目块不跨页，两页内容密度保持接近，消除第一页拥挤和第二页大面积留白。
- 不加入照片、年龄、婚姻等与岗位判断无关的信息。

## 链接与安全

- 保留当前在线演示链接，并验证 PDF 中链接可点击。
- 当前代码仓库曾存在凭据历史和未完成收尾项，本轮不在简历中展示仓库链接。
- 不在简历、生成脚本或交付目录中写入任何 API Key、数据库密码或内部敏感信息。
