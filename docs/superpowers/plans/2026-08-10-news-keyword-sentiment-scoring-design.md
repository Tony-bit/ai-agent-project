# 新闻关键词情感评分设计

## 背景

当前新闻分析链路能够通过 `IStockDataProvider` 获取新闻，并由 `NewsAnalystNode` 生成新闻分析正文。V3 决策信号由 `NewsRatingAlgorithm` 根据 `NewsItemVO.sentimentScore` 聚合得到新闻评分和整体情感，但当前 `SinaNewsDataProvider` 返回的新闻没有情感分数，因此新闻信号会以 `no news item has a sentiment score` 标记为 `UNAVAILABLE`。

本次改动在不增加新闻源、不增加 LLM 调用、不改变现有聚合阈值的前提下，为当前检索到的标题和摘要增加一版固定、可复现的关键词评分能力。

## 目标

- 使用新闻标题和摘要为单条新闻生成 `[-1, 1]` 范围内的 `sentimentScore`。
- 让现有 `news-rating-v1` 能够聚合至少一条可评分新闻，输出可用的新闻评分和整体情感。
- 保持 Provider 只负责外部接口访问和数据标准化，不在 Provider 内实现业务评分。
- 保留外部数据源未来提供的原生情感分数，不覆盖非空 `sentimentScore`。
- 对无法可靠判断的新闻保持 `null`，不把未知值伪装成中性分数 `0`。
- 通过算法版本和固定规则保证相同输入得到相同输出。

## 非目标

- 不新增 AKShare、Tushare、Google News 等新闻源。
- 不恢复 V2 新闻分析师的结构化 LLM 评分。
- 不增加额外 LLM 分类调用。
- 不实现可热更新的 YAML 或数据库规则配置。
- 不在本次改动中引入新闻时效、来源可信度或相关性加权。
- 不修改 `NewsRatingAlgorithm` 现有的聚合阈值。

## 方案选择

### 采用方案：独立的确定性关键词评分层

在 Provider 与新闻分析节点之间增加独立评分组件。组件读取标准化后的 `NewsItemVO`，仅对缺失 `sentimentScore` 的条目计算分数。

该方案具备以下特点：

- 与外部数据源解耦，未来切换 Provider 时可以复用。
- 不依赖 LLM 输出格式，延迟和成本稳定。
- 规则和权重随代码版本发布，便于测试、审计和复现。
- 第一版精度有限，因此坚持高精度、低覆盖率，未命中规则时返回空值。

### 未采用方案

1. 在 `SinaNewsDataProvider` 内直接评分：实现简单，但混合了外部适配与业务判断，后续每个 Provider 都会重复实现。
2. 解析新闻分析师正文得到分数：自然语言正文不具备稳定机器契约，容易出现格式和语义漂移。
3. 新增结构化 LLM 分类调用：语义能力更强，但增加延迟、费用和故障点，不适合作为第一版。

## 架构

```text
外部新闻接口
    -> IStockDataProvider / SinaNewsDataProvider
    -> NewsItemVO 列表
    -> NewsItemSentimentEnricher
        -> NewsKeywordSentimentScorer
    -> NewsAnalystNode 生成分析正文
    -> DecisionSignalShadowService
    -> NewsRatingAlgorithm(news-rating-v1)
    -> newsRating / newsOverallSentiment
```

### `NewsKeywordSentimentScorer`

职责：根据单条新闻的标题和摘要计算确定性情感分数。

输入：`NewsItemVO`。

输出：内部评分结果，包含：

- `score`：`[-1, 1]` 范围内的分数；无可靠命中时为空。
- `matchedRules`：命中的规则标识，仅用于测试和日志诊断，不进入公开 API。

算法版本：`news-keyword-score-v1`。

该组件不修改输入对象，保持纯函数语义，方便独立单元测试。

### `NewsItemSentimentEnricher`

职责：遍历新闻列表并填充缺失的单条新闻评分。

行为约束：

- 列表为空时直接返回。
- 条目为空时跳过。
- `sentimentScore` 非空时保留原值。
- 评分器返回空值时继续保留 `null`。
- 评分器返回有效值时写入对应 `NewsItemVO.sentimentScore`。
- 记录总条数、原生分数条数、规则评分条数和未评分条数，不记录完整新闻正文。

### 接入位置

`NewsAnalystNode` 在调用 `getNews(10)` 后、构建 LLM 输入前调用 `NewsItemSentimentEnricher`。

这样可以保证：

- LLM 输入中能够看到规则生成的情感分数，正文分析与最终确定性信号使用同一份新闻快照。
- 后续 `DecisionSignalShadowService` 无需改变，仍从 `NewsReportVO.newsItems` 读取分数。
- `NewsRatingAlgorithm` 无需改变，继续忽略空分数并对有效分数求平均。

## 文本预处理

评分文本由标题和摘要组成，标题权重高于摘要。预处理步骤如下：

1. 将 `null` 转为空字符串。
2. 去除 HTML 标签并还原常见 HTML 实体，避免 `<em>` 等标签影响匹配。
3. 统一全角和半角空白，合并连续空白。
4. 标题和摘要分别匹配规则，不进行分词，不依赖外部 NLP 库。

全文内容不参与第一版评分，因为当前新闻源多数只稳定提供标题和摘要。

## 规则模型

### 规则类别

规则按以下优先级执行：

1. 组合规则：表达完整业务语义，优先于普通关键词。
2. 高影响事件规则：监管、退市、重大资本动作等。
3. 普通方向规则：增长、下降、获批、中标等。
4. 程度修饰规则：只调整已命中的方向分，不独立产生方向。

### 初始组合规则

| 规则 | 分数 | 说明 |
|---|---:|---|
| `扭亏为盈` | `+0.75` | 明确盈利改善 |
| `亏损收窄` | `+0.35` | 仍亏损但边际改善 |
| `亏损扩大` | `-0.70` | 盈利能力继续恶化 |
| `增长不及预期`、`低于预期` | `-0.60` | 正向增长被预期差反转 |
| `超出预期`、`超预期` | `+0.60` | 明确正向预期差 |
| `下调评级` | `-0.60` | 机构观点恶化 |
| `上调评级` | `+0.55` | 机构观点改善 |
| `解除质押`、`解押` | `+0.20` | 风险轻度缓解 |
| `新增质押` | `-0.30` | 股东层面风险轻度上升 |

组合规则命中后，其覆盖的普通词不重复计分。例如命中 `亏损收窄` 后，不再单独计算 `亏损`。

### 初始正向规则

| 关键词 | 分数 |
|---|---:|
| `涨停` | `+1.00` |
| `暴涨` | `+0.90` |
| `大涨` | `+0.80` |
| `创新高` | `+0.70` |
| `回购` | `+0.65` |
| `获批`、`批准` | `+0.60` |
| `中标`、`签署重大合同` | `+0.60` |
| `增持` | `+0.55` |
| `净利润增长` | `+0.50` |
| `营收增长` | `+0.40` |
| `纳入国家基本药物目录`、`纳入基药目录` | `+0.45` |
| `突破` | `+0.35` |

### 初始负向规则

| 关键词 | 分数 |
|---|---:|
| `退市` | `-1.00` |
| `跌停` | `-1.00` |
| `暴跌` | `-0.90` |
| `立案调查`、`被立案` | `-0.80` |
| `重大违法` | `-0.80` |
| `处罚` | `-0.65` |
| `诉讼` | `-0.55` |
| `减持` | `-0.50` |
| `净利润下降`、`净利润下滑` | `-0.50` |
| `营收下降`、`营收下滑` | `-0.40` |
| `违约` | `-0.75` |
| `风险警示` | `-0.70` |

### 程度修饰

程度词只对同一文本片段内已经命中的方向分生效：

- `大幅`、`显著`、`大增`、`大降`：绝对值乘以 `1.20`。
- `小幅`、`轻微`、`略有`：绝对值乘以 `0.70`。

每个标题或摘要最多应用一次程度修饰，最终分数仍限制在 `[-1, 1]`。

### 标题与摘要权重

- 标题命中权重：`1.0`。
- 摘要命中权重：`0.6`。
- 同一规则同时出现在标题和摘要时只取标题命中，避免重复计算。

条目总分为所有非重叠规则得分之和，随后限制到 `[-1, 1]`。

### 空值语义

- 至少命中一条有方向的规则：返回数值分数，包括正负规则互相抵消后的 `0.0`。
- 没有命中任何有方向规则：返回空值。
- 空标题且空摘要：返回空值。

因此，`0.0` 表示存在可识别但相互抵消的事件影响，`null` 表示没有足够规则证据，两者不得混用。

## 数据流示例

### 正向事件

```text
标题：羚锐制药4个药品新纳入国家基药目录
命中：纳入国家基本药物目录 +0.45
结果：sentimentScore = 0.45
```

### 混合事件

```text
标题：股东解除质押975万股，同时新增质押508万股
命中：解除质押 +0.20，新增质押 -0.30
结果：sentimentScore = -0.10
```

### 无法判断

```text
标题：公司发布2026年第一季度报告
摘要：公司营业总收入为11.26亿元
命中：无
结果：sentimentScore = null
```

## 错误处理与可观察性

- 评分组件不得因单条新闻异常中断新闻分析节点。
- 非法原生分数不在本次评分层自动修正；由既有数据完整性检查负责暴露。
- 评分完成后记录一条汇总日志：算法版本、总条数、原生分数数、规则评分数和未评分数。
- 调试日志可以记录新闻标题摘要、命中规则标识和最终分数，但不得记录全文内容。
- 若全部新闻仍不可评分，维持现有 `UNAVAILABLE` 行为及原因，不降级为固定 3 分。

## 测试策略

### `NewsKeywordSentimentScorerTest`

- 正向关键词得到预期分数。
- 负向关键词得到预期分数。
- `亏损收窄`、`增长不及预期` 等组合规则覆盖普通词。
- 标题权重高于摘要权重。
- 同一规则在标题和摘要中不重复计算。
- 正负事件同时出现时正确求和。
- 程度词正确放大或减弱绝对值。
- HTML 标签不影响匹配。
- 无规则命中返回空值。
- 输出始终处于 `[-1, 1]`。

### `NewsItemSentimentEnricherTest`

- 原生非空分数不会被覆盖。
- 缺失分数且规则命中时被补齐。
- 缺失分数且规则未命中时保持为空。
- 空列表、空条目和空文本不会抛出异常。

### 集成回归

- `NewsAnalystNode` 构建 LLM 输入前完成评分增强。
- 至少一条可评分新闻时，`NewsRatingAlgorithm` 返回 `AVAILABLE`。
- 全部不可评分时仍返回 `UNAVAILABLE`。
- 现有 `news-rating-v1` 阈值边界测试保持不变。

## 发布与兼容性

- 不改变外部 API 字段结构。
- 不改变历史 `NewsItemVO.sentimentScore` 的取值范围。
- 不改变 `news-rating-v1` 的算法版本和阈值。
- 新增单条新闻评分算法版本 `news-keyword-score-v1`，在日志中记录。
- 第一版规则随应用发布，不支持运行时修改；规则发生语义或权重变化时必须升级算法版本。

## 验收标准

1. 当前新浪新闻检索结果中，包含明确事件关键词的条目能够获得 `sentimentScore`。
2. 羚锐制药示例中的“获批”“纳入基药目录”“解除质押/新增质押”能够产生可解释分数。
3. 新闻最终信号不再因为所有分数为空而必然不可用。
4. 无法判断的普通披露新闻不会被错误填为中性分数。
5. 所有新增和现有相关单元测试通过。
