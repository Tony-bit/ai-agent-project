# AI Agent 前端产品化打磨设计

日期：2026-06-21  
状态：待用户书面审阅

## 1. 背景

项目已经具备统一 Agent 入口、意图路由、多任务拆解、多 Agent 股票分析、会话记忆、Persona 注入、情景记忆检索、SSE 流式输出、重试降级和 Langfuse 可观测性。现阶段不再增加新的 Agent 能力，也不为面试编写只对固定 Query 生效的演示功能，而是对现有 HTML 前端做产品级 Bugfix 和细节打磨。

本轮工作的目标是让已有能力在正常、异常和长时间流式执行场景中表现稳定，页面状态与后端真实状态一致，用户输入和模型输出安全可控，并让现有执行过程更容易理解和验收。

## 2. 设计原则

1. 不迁移 React、Vue 或其他前端框架，继续维护现有原生 HTML、JavaScript、Tailwind CSS 页面。
2. 不新增“路由实验台”“记忆实验室”等独立业务模式。
3. 不在前端硬编码、自动填充或自动执行面试演示 Query。
4. 不修改核心 Agent 编排架构，不重做后端领域模型。
5. 优先修复影响正确性、安全性和演示稳定性的缺陷，再做低风险体验优化。
6. 每批修改都独立验证和交付，避免三批代码同时展开。
7. 保留当前工作区对 `currentUserId` 的用户修改；涉及同一区域时采用兼容改造，不覆盖用户意图。

## 3. 当前问题

### 3.1 SSE 流解析不完整

当前实现对每个网络 chunk 直接按换行拆分并解析 `data:`。SSE 消息可能跨 chunk 到达，半条 JSON 会被当作非法数据忽略，造成事件偶发丢失。流结束时也没有统一冲刷解码器和剩余缓冲区。

### 3.2 输出渲染存在注入风险

页面已经加载 DOMPurify，但模型 Markdown 经过 `marked.parse` 后直接写入 `innerHTML`，没有执行清洗。用户消息也存在直接插入模板字符串的路径。模型输出和用户输入都属于不可信内容，需要在进入 DOM 前统一处理。

### 3.3 完成状态与结果面板归类不一致

通用 Agent 和股票分析使用的完成事件不完全相同。当前前端对 `final`、`complete`、`summary`、`trading_complete` 的关闭 Loading、恢复按钮和结果面板归类规则分散，可能出现结果进入思考面板、重复追加完成提示或请求结束后仍处于忙碌状态。

### 3.4 请求生命周期缺少统一控制

通用对话和股票分析分别实现了一套 Fetch、流读取、异常处理和按钮恢复逻辑。两套逻辑容易漂移，也没有统一处理重复提交、用户取消、页面切换和网络断流。

### 3.5 运行配置写死

API 使用绝对地址 `http://localhost:8090`，限制了反向代理、不同端口和部署环境。用户 ID 在源码中写死，不利于验证跨用户隔离和跨会话记忆，同时直接删除默认值又会破坏当前演示习惯。

### 3.6 交互反馈不够产品化

部分校验和忙碌提示使用阻塞式 `alert`。错误、空状态、长内容、窄屏布局和连续流式更新的反馈仍可统一，避免面试演示中出现页面像调试工具而非完整产品的感觉。

## 4. 总体设计

本轮不改变页面的两个业务入口：通用对话和股票分析。修改集中在四个内部边界：

- 流传输边界：统一解析 SSE，保证跨 chunk 消息完整。
- 安全渲染边界：统一转义用户文本并清洗 Markdown HTML。
- 请求状态边界：统一管理 idle、running、completed、failed、cancelled 状态。
- 运行配置边界：统一解析 API Base URL 和 userId，同时保留本地默认行为。

路由、记忆、多任务和多 Agent 等已有能力继续通过现有“AI 思考执行过程”和“最终执行结果”展示。本轮仅修正事件标签、归类和状态呈现，不新增专用页面或面试特制流程。

## 5. 分批实施

### 第一批：流式正确性与安全

目标：消除可能导致内容丢失、页面卡死和不安全渲染的高优先级问题。

变更内容：

1. 抽取统一 SSE 解析器，维护跨 chunk 文本缓冲区。
2. 支持 `\n\n` 和 `\r\n\r\n` 事件边界，忽略注释行，合并同一事件的多个 `data:` 行。
3. 流结束时冲刷 `TextDecoder` 和剩余完整事件；不把不完整 JSON 静默当作成功。
4. 为每次请求清理流式消息缓存，防止前一次请求污染下一次请求。
5. 模型 Markdown 使用 `marked.parse` 后必须经过 DOMPurify 清洗。
6. 用户输入统一通过文本节点或 HTML 转义方法渲染。
7. 代码高亮只作用于清洗后生成的 `pre code` 节点。
8. 修复通用与交易流的完成事件归类，确保最终内容进入结果面板。
9. 去除由网络流结束和业务完成事件共同触发的重复“执行完成”提示。

验收标准：

- 人工构造被任意拆分的 SSE JSON 后，事件仍能完整解析。
- 包含脚本标签、事件属性和危险链接的用户输入或模型 Markdown 不执行脚本。
- 通用对话和股票分析在成功、业务错误、断流三种情况下都能恢复按钮和 Loading。
- 最终结果只出现一次，并进入最终结果面板。

### 第二批：请求生命周期与运行配置

目标：让页面在连续操作、取消任务和不同部署环境下保持状态一致。

变更内容：

1. 为通用和交易请求建立共享的请求控制器及统一状态转换。
2. 使用 `AbortController` 支持主动取消当前请求。
3. 请求运行期间禁止重复提交，但允许用户明确取消。
4. 将成功、失败、取消和断流的清理逻辑集中到单一收口函数。
5. API 默认改为同源相对路径；允许通过页面 URL 参数或本地配置覆盖 API Base URL。
6. userId 的解析顺序固定为：URL 参数、localStorage、页面默认值。
7. URL 或 localStorage 中的 userId 经过长度和字符校验后才能使用。
8. 保留当前测试用户 ID 作为无配置时的默认值，保证现有记忆数据仍可演示。
9. 使用非阻塞 Toast 替换输入校验、忙碌状态和请求错误相关的 `alert`。
10. 新建会话、切换会话和切换业务入口时不遗留前一个请求的视觉状态。

验收标准：

- 快速连续点击发送只产生一个后端请求。
- 用户取消后，读取器停止、按钮恢复，并显示“已取消”而非“系统失败”。
- 页面通过 Nginx 同源部署时不依赖固定的 localhost 地址。
- `?userId=demo-user` 可覆盖默认用户，刷新页面后行为符合已定义的持久化规则。
- 通用和交易模式的 Loading、按钮文案及状态点行为一致。

### 第三批：体验细节、测试与交付材料

目标：在不改变产品结构的前提下完成视觉和验收收尾。

变更内容：

1. 统一空历史、无结果、错误和取消状态的文案与样式。
2. 优化长 Markdown、长代码块、超长英文和连续流式内容的换行与滚动。
3. 调整窄屏下侧栏、双面板和输入区布局，保证核心操作可用。
4. 为按钮、输入框和状态变化补充必要的可访问名称、焦点和禁用态。
5. 对现有路由、记忆、分析、执行、监督、总结和交易事件补齐可读标签；未知事件使用通用降级展示。
6. 不显示模型原始思维链，仅显示后端已经返回的阶段性执行摘要。
7. 增加与本轮变更匹配的单元测试或纯函数测试。
8. 编写前端回归清单，覆盖通用对话、股票分析、会话历史、记忆同步和异常恢复。
9. 更新面试演示文档，只记录建议验证步骤，不把 Query 写入产品前端。

验收标准：

- 桌面宽屏和常见窄屏尺寸下不存在遮挡核心按钮的布局问题。
- 未知 SSE 类型不会导致 JavaScript 异常或页面停止更新。
- 长内容可阅读、代码块可横向滚动、面板自动滚动不阻止用户回看历史。
- 回归清单中的场景均有明确的前置条件、操作和预期结果。
- 默认测试和本轮新增测试通过。

## 6. 组件与数据流

### 6.1 前端内部组件边界

现有单文件页面暂不进行框架迁移。为降低改动风险，优先在现有脚本内抽取职责清晰的函数：

- `resolveRuntimeConfig`：解析 API Base URL 和 userId。
- `createSseParser`：接收文本 chunk 并产出完整事件。
- `sanitizeMarkdown`：Markdown 转换与 DOMPurify 清洗。
- `renderUserText`：安全渲染用户文本。
- `classifyAgentEvent`：决定事件的标签、目标面板和终止语义。
- `requestLifecycle`：管理请求状态、取消控制器和 UI 恢复。

只有当现有文件继续增长导致测试无法隔离时，才在实施计划中将纯 JavaScript 抽到同目录独立文件；不做大规模目录重构。

### 6.2 SSE 数据流

1. 用户从现有通用或交易入口提交请求。
2. 请求生命周期进入 running，禁用重复提交并显示取消入口。
3. Fetch 返回字节流，TextDecoder 将字节转换为增量文本。
4. SSE 解析器缓存半包，只输出完整事件。
5. JSON 事件交给事件分类器确定目标面板、展示标签和是否终止。
6. 内容经过安全渲染后追加或更新对应消息。
7. 收到业务完成、网络结束、失败或取消后，生命周期只执行一次收口。

## 7. 错误处理

- HTTP 非 2xx：读取可用的错误信息并转为用户可理解的 Toast 与面板错误卡片。
- SSE JSON 非法：记录有限长度的诊断信息，当前事件显示为协议错误，但不泄露完整响应。
- 网络断流：若尚未收到业务完成事件，则标记为异常中断；已完成后断开不重复报错。
- 用户取消：单独标记 cancelled，不进入失败统计。
- DOMPurify 或 marked 不可用：停止富文本渲染，降级为纯文本，而不是继续写入未清洗 HTML。
- localStorage 不可用：降级使用当前页面内存配置，不阻断对话。
- 未知事件类型：使用通用阶段卡片展示，不影响后续事件处理。

## 8. 测试策略

测试按风险分层：

1. 纯函数测试：覆盖 SSE 半包、多个事件、CRLF、多 `data:` 行、非法 JSON、结束冲刷、事件分类和配置解析。
2. 安全测试：覆盖 script、`onerror`、`javascript:` URL、恶意 Markdown 和普通代码块。
3. 页面手工回归：覆盖通用对话、股票分析、会话列表、历史加载、新建会话、清空会话、记忆同步、取消和错误恢复。
4. 后端回归：本轮原则上不修改核心后端；若实现中发现必须修正 SSE 契约，则为对应实体和发送逻辑补充定向单元测试。
5. 完整回归：在第三批结束后运行项目默认测试，并记录无法在离线环境验证的外部服务场景。

## 9. 每批交付方式

每一批独立执行以下闭环：

1. 开始前确认本批文件范围和现有工作区差异。
2. 只修改本批相关代码和测试。
3. 运行定向测试与静态检查。
4. 输出变更摘要、验证结果和剩余风险。
5. 由用户执行真实服务端到端演示并反馈问题。
6. 修复本批反馈后，再进入下一批。

三批之间不并行展开，上一批未完成验收时不提前修改下一批代码。

## 10. 明确不做

- 不新增前端框架或构建工具链。
- 不新增独立路由、记忆演示页面或业务页签。
- 不在前端保存固定演示 Query。
- 不增加 Mock 回放模式。
- 不展示或推导模型原始思维链。
- 不为了拆文件而全面重构 97KB HTML。
- 不调整 Agent 路由算法、Prompt、记忆策略或股票分析图。
- 不清理与本轮目标无关的仓库文件和用户改动。

## 11. 完成定义

全部三批完成需要同时满足：

1. 第一批和第二批的正确性、安全性及状态验收项全部通过。
2. 第三批回归清单完成，核心场景无阻塞缺陷。
3. 默认测试没有因本轮修改新增失败。
4. 页面无需固定 Query 即可真实展示现有 Agent 能力。
5. 用户能够独立执行端到端演示，且异常后无需刷新页面即可继续下一次演示。
