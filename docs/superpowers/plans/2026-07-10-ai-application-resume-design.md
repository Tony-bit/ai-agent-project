# AI 应用开发工程师简历设计

## 目标

基于现有 PDF 简历，制作一份约两页的中文 AI 应用开发工程师主版本，强化 Agent 工程落地能力，同时以华为和 Shopee 的大规模后端实践证明工程能力。

## 交付物

- 一份采用标准 OpenXML、可由 WPS 直接编辑的 DOCX 简历。
- 一份内容和分页一致的 PDF 简历。
- 文件保存到原简历所在目录，不覆盖原 PDF。

## 定位与信息原则

- 目标岗位统一为“AI 应用开发工程师 / Agent 平台开发工程师”。
- 职业摘要采用“3.5 年头部互联网后端经验 + AI Agent 项目经验”的可核验表述，不把项目时间直接等同为正式工作年限。
- 仅使用原简历中已有事实和指标，不补造数据。
- Agent 项目缺失的关键指标以醒目的待补充项标记，便于后续完善。
- 不擅自判定 Agent 项目属于个人、开源、创业或任职项目；成品暂放在“项目经历”中，待用户确认后再补充项目性质。

## 两页结构

### 第一页

1. 姓名、目标岗位及联系方式。
2. 职业摘要：大厂经历、后端规模、性能成果和 AI 工程方向。
3. 教育经历。
4. 工作经历：华为、Shopee，保留职责范围和代表性规模，不与项目经历重复铺陈。
5. Agent 智能体平台：使用自然 STAR 表述，突出统一入口、多 Agent 编排、SSE、数据工具、记忆与可观测、微调评测。

### 第二页

1. 用户增长榜单微服务：突出 15 亿+日调用、TP99、Redis、配置效率和 AI 巡检结果。
2. 物流供应链容器微服务：突出消息乱序治理方案，并保留真实结果的待补充项。
3. 智能驾驶云基础服务：突出 10 万辆车在线和监控体系，保留个人行动与效果的待补充项。
4. 技能矩阵：按语言框架、数据中间件、AI 工程和工程能力压缩为四组。

## 文案规则

- 每个项目要点尽量包含“问题/目标 + 个人行动 + 结果”。
- 使用“主导、设计、实现、参与”等词明确个人责任边界。
- 统一 Java、Spring Boot、MySQL、Kafka、Elasticsearch、pgvector 等技术名称。
- 避免“精通”“深入理解”等无法由经历直接证明的泛化自评。
- 不使用“搜广推”概括未被具体项目完整证明的领域经验。
- 对“Redis 减少 30%（12G）”等口径不清的数据作待确认标记，不擅自选择解释。

## 版式规则

- A4，两页左右；单栏、ATS 可解析。
- 姓名作为页首主标题，联系方式压缩为一行。
- 深蓝色用于标题，正文以深灰/黑色为主，不使用复杂图表或技能进度条。
- 正文保持适合打印和屏幕阅读的字号与行距。
- 缺失信息采用浅黄色高亮，正常内容不使用高亮。

## 验收标准

- DOCX 可由 WPS 正常打开和编辑，PDF 可正常复制文字；生成过程不依赖 Microsoft Office。
- 求职定位、技术名称、日期格式和项目名称一致。
- 不出现未经原简历支持的新指标或经历。
- 第三页不存在；如果因渲染差异出现第三页，只允许极少量调整间距，不牺牲可读性。
- 原 PDF 保持不变。
